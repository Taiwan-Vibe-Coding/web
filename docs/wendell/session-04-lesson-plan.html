Day 4 · Session 4 · 課程計畫

從工作痛點到第一個 STDIO MCP 小成品

用 Codex 建立本機、唯讀、可測試的工作小工具

日期：2026-07-31（五）・結業

時長：3 小時

對象：全體學員；每人在新專案「穩得 AI 工作小工具」的個人練習資料夾完成一個 MCP 小成品。可互相討論，但不可只觀看他人操作。

工具：Codex 桌面 App + 本機 STDIO MCP + Session 2／3 雲端穩得 MCP

需要 ERP 連線：前兩小時 ❌（本機訂單 Excel／STDIO）；結業一小時 ✅ 雲端穩得 MCP（設定卡 demo，非正式系統）

今日範圍：前 2 小時以本機、唯讀的模糊化訂單 Excel，先做不連 MCP 的查詢，再建立兩個工具的 MCP；最後 1 小時切回雲端穩得 MCP，做複合查詢與 preview → confirm 判讀（寫入先預覽，未同意不送出）。不在「穩得業務工具」專案修改任何內容。

課程目標

  1. 說出 Plugin、MCP 與 STDIO MCP 的差別，以及何時不需要自製 MCP。
  2. 把一個日常工作問題寫成「工具名稱、輸入、輸出、限制」的規格。
  3. 用 Codex 在自己的電腦建立並啟動一個唯讀 STDIO MCP；理解這是以 Vibe Coding 完成的程式小成品。
  4. 以正常、找不到資料、錯誤輸入三類問題測試 MCP。
  5. 判斷一個原型是否值得交給 MIS／技術人員進一步評估，而不是直接碰正式資料。
  6. 寫出自己的 System Prompt，並將 MCP 小成品放進部門「凡事問 AI」工作手冊。
  7. 以雲端穩得 MCP 完成一次複合查詢與一次 preview → confirm 預覽判讀；能說出何時不應確認送出。

本堂與課後的兩份練習資料

課堂以同一份模糊化訂單 Excel先做不連 MCP 的工作，再做 MCP，直接比較差別；設備借用資料保留為安全、可重複的課後練習。

全員成功標準：每人先完成訂單 Excel 的不連 MCP 查詢，再讓自己的 Codex 呼叫訂單 MCP 的兩個工具，並至少完成一項正常查詢與一項錯誤處理測試；能說明兩種方式的差別。遇到安裝或啟動阻塞者，先完成需求卡與程式檢查，課後補跑，不以觀看他人成果代替。

各節詳細內容

13:00–13:15 開場：什麼情況值得做 MCP？

  • 回顧前三堂：提示詞能整理使用者提供的內容；MCP 才能把明確工具與資料來源交給 Codex 使用。
  • 說明本堂只做 STDIO：它在自己的電腦上由命令啟動，適合學習與原型，不是公司共用服務。
  • 說明前兩小時不做的事：不連 ERP、沒有 Bearer、沒有真實個資、本機工具不寫入、不發布；結業一小時才切回雲端穩得 MCP。

先分清楚：Plugin、App 與 MCP

類別一句話主要功能課堂例子
Plugin一個工作流程的能力包可把 Skills、App 與範本組合起來，方便安裝與管理「文件整理」Plugin：帶有整理流程指引，並可選擇連接文件 App
App連到既有外部服務的接頭在原系統權限內讀取或執行允許的動作Google Drive：找已授權文件；Notion：讀取知識庫；行事曆：查看可用時段
MCP讓 AI 使用專用資料與工具的介面定義工具名稱、輸入、輸出與限制；可為本機 STDIO 或受控服務本堂的訂單查詢 MCP：列出訂單、查單據明細

好記法：Plugin 是工具箱；App 是已裝好的外部接頭；MCP 是為特定工作設計的專用工具。三者可以搭配，但不是同一件事。

六個情境：應該用哪一種？

工作情境優先選擇原因
把已去識別化的會議筆記整理成待辦表不需 Plugin／App／MCP直接把已授權文字交給 Codex 即可。
找共用雲端硬碟中最新核准的 SOPApp資料已在既有文件服務；重點是權限與限定資料夾，不是重做資料系統。
想把固定的「會議整理＋待辦表＋追蹤信」做成常用工作流程Plugin可把操作指引、提示詞範本與需要的 App 打包成可重複使用的流程。
查本機虛構 CSV 中哪些設備仍在借用STDIO MCP資料格式固定、會重複查詢，值得做成兩個明確的唯讀工具。
查正式 ERP 的付款狀態並自動付款暫不製作先釐清資料正確性、授權、稽核與 preview → confirm；不能因為能做就直接自動化。
把實驗室排程、設備狀態與委託案進度整合查詢先需求盤點，可能是 MCP若資料分散、多畫面反覆查，且現成 App 無法處理，才列為自製 MCP 候選。

概念說明參考 OpenAI 的 Plugins in ChatGPT and Codex 與 Model Context Protocol；實際可用 Plugin、App 與權限仍以工作區設定為準。

講師提問：「若只靠貼資料就能完成，還需要 MCP 嗎？」只有重複、資料格式固定、需要被可靠查詢時，才值得做成工具。

13:15–13:35 練習一：不連 MCP，也能先完成業務查詢

每人將講師提供的模糊化訂單 Excel 複製到新專案「穩得 AI 工作小工具」的個人練習資料夾，在 Codex 直接詢問：訂單摘要、依交期的追蹤清單，以及指定單據明細。先看它能做什麼、又有哪些地方需要人工核對。

  • 一份檔案、一次任務時，直接用 Codex 是否已足夠？
  • 同樣問題明天再問、換人再問時，提示詞與結果格式是否容易一致？
  • 跨幣別金額、資料不足或未知欄位，是否有被明確標示「待確認」？

訂單資料提醒：模糊化不等於可公開。只可在本機個人練習資料夾使用；不可上傳 GitHub、群組、外部雲端或貼入公開教材。

13:35–14:25 練習二：把同一份訂單資料做成 MCP

每人把剛才的重複查詢需求寫成工具規格，再在自己的「穩得 AI 工作小工具」練習資料夾中建立訂單 MCP。可請鄰座協助核對規格與資料欄位，但每人都要親自以 Codex 建立、啟動並測試自己的版本。使用 練習題的建置提示詞，先讓 Codex 提出檔案結構與工具規格，確認後才建立程式。

安全規則：只允許 Codex 在這次新建的練習資料夾內工作；不得把帳密、Bearer、真實資料或其他資料夾提供給它；不得改動「穩得業務工具」。若原型未來要接公司資料，由 MIS／Cursor 另行評估正式整合。

14:25–14:50 練習三：連接與測試訂單 MCP

  1. 在 Codex 的 MCP servers 設定中加入本機 STDIO 伺服器；儲存並重新啟動。
  2. 以 /mcp 或 MCP servers 清單確認已啟用。
  3. 依練習題跑三類驗收測試：A 正常查詢、B 指定單據明細、C 查無或錯誤輸入；每類至少選 1 題（合計至少 3 題）。
  4. 檢查回答是否只依工具資料回覆、是否明確標出未知或錯誤。

14:50–15:00 練習四：比較與驗收

  • 比較同一個訂單問題：直接用 Codex 與 MCP 查詢，哪種情況各自較適合？
  • 修改工具說明與回傳格式，讓人一眼看懂客戶、幣別、交期與待確認處。
  • 用驗收卡確認：唯讀、限定資料夾、無敏感資料、錯誤可理解。

15:00–15:10 核心一：寫你的 System Prompt

System Prompt 讓 Codex 在每次新任務開始時，知道你的角色、常見工作、輸出格式與限制。今天不要求長篇介紹，只求可實際貼用的一段版本。

我是穩得實業的＿＿＿＿部門＿＿＿＿。
我常需要處理＿＿＿＿、＿＿＿＿、＿＿＿＿。
請用繁體中文條列回覆；事實不足時標示「待確認」，不要自行猜測。
涉及資料或工具結果時，請說明資料來源與限制。

每人以一個常用工作問題快速測試並修改一次；詳見練習題「結業一小時」。

15:10–15:25 核心二：ERP 複合查詢判讀

切回 Session 2／3 的雲端穩得 MCP（設定卡／Bearer），依練習題提示詞做一次「未付應付 + 採購單 + 廠商條件／聯絡人」複合查詢。學員核對回覆是否真的呼叫 MCP、資料是否串接完整；哪一筆要付款、是否催貨，仍由人決定。

講師備註：若本機訂單 MCP 與雲端穩得同時啟用，請提醒學員這一題要用雲端工具；看不到工具時先查 /mcp 與設定卡。

15:25–15:45 核心三：安全寫入判讀——preview → confirm

仍用雲端穩得 MCP，以「新增測試客戶」做預覽（confirm=false），核對名稱前綴、國別與待確認事項，再決定是否應該確認送出。預設學員只做到預覽；僅在講師同意且前綴正確時，才允許 confirm=true。

與 STDIO 小成品的差別：前兩小時的本機工具是唯讀、虛構／模糊化資料；此處回到受控雲端 demo，練習寫入安全判斷。正式系統的讀取與寫入，均須由授權流程與 MIS 另行管理。

15:45–15:55 核心四：部門「凡事問 AI」工作手冊

將今天的 STDIO MCP 小成品、ERP 複合查詢與一項日常提示詞工作，放進同一張手冊；標出哪些事仍需人工確認。

15:55–16:00 結業展示：下一個值得做的 MCP

每人先完成自己的驗收；再由代表以 1 分鐘展示共同題目的其中一個版本：

  1. 我們解決的工作問題。
  2. 兩個工具各做什麼。
  3. 哪一個測試最能證明它可用。
  4. 若未來接公司資料，需要誰核准、先做什麼風險檢查。

結業帶走：每個人都完成過一次 MCP：把需求說清楚、請 Codex 產生程式、在本機啟動、測試與說明限制。這不等於能直接維護正式系統；正式導入仍需 MIS 處理權限、稽核與維護責任。

本堂講義重點

先做暫時不做
本機 STDIO、虛構資料、唯讀、兩個工具、人工測試雲端部署、多人共用、OAuth、ERP 寫入、自動寄信
最小權限：只讀指定資料夾把整台電腦或公司共用磁碟交給工具掃描
未知就回覆找不到／待確認自行補寫事實或假裝資料存在
